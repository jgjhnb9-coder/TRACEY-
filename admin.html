SITE PUBLISHING GUIDE

Manage TRACEY.

This page is a guide to editing the repository — it is not a login page or a security boundary.

Publishing access is controlled by GitHub.

Only people granted repository write access can save changes to the live website. GitHub may ask you to sign in before editing.

Before publishing: the repository owner must enable GitHub Pages and choose GitHub Actions as the source. Open Pages settings ↗. After a commit, check GitHub Actions ↗ and wait for the deployment run to succeed.

COMMENTS SETUP — OWNER ACTION REQUIRED

Finish Giscus configuration

  1. The repository owner opens Repository Settings ↗, then General → Features, and enables Discussions.
  2. Install or authorize the Giscus GitHub App ↗ for this repository.
  3. Open giscus.app ↗, enter jgjhnb9-coder/TRACEY-, choose a category, and copy the generated Repository ID, Category name and Category ID.
  4. Open content/settings.json ↗ and paste the exact values into giscus.repoId, giscus.category and giscus.categoryId. Do not guess them.
  5. Commit the file. Test comments on an individual published article. Visitors may need to sign in to GitHub to comment.

Giscus is not active while these values are blank. It uses GitHub Discussions; it does not create a separate comment database.

ANDROID PUBLISHING STEPS

ANDROID PUBLISHING STEPS

Publish from your phone

  1. Open the relevant link above. Sign in to GitHub if asked.
  2. Tap the pencil/edit control. For photos, use Add file → Upload files.
  3. Make your changes carefully. Keep JSON commas, quotation marks and brackets valid.
  4. Scroll to Commit changes, add a short description, then commit to main.
  5. GitHub Actions will publish the update. Check the Actions tab if the site does not update.

Never add passwords, personal access tokens or private credentials to website files. Draft articles stay out of public pages while their status is draft.
